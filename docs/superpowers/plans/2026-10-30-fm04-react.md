# FM04 — SkillHub en React : plan d'implémentation

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Transposer toute la landing SkillHub (FM03, sans framework) en une application React routée dans `react/`, avec inscription au site, inscription aux ateliers, données JSON, et la publier sous `/CDWS-2027-FilRouge/react/`.

**Architecture:** Projet Vite autonome dans `react/` (son `package.json`, ses tests), rangé comme l'exige la fiche EC02 (`src/components`, `src/views`, `src/router`, `src/hooks`, `src/services`, `src/contexts`). Les modules sans DOM de FM03 sont repris tels quels ; React Router en mode déclaratif ; l'état partagé dans trois contextes à hook maison ; Tailwind configuré avec les jetons de FM02. Une GitHub Action publie le site actuel (Jekyll, comme aujourd'hui) et l'application.

**Tech Stack:** Vite 8.3.5, React 19.3.1, TypeScript 7.0.2, React Router 8.5.1, Tailwind CSS 4.3.3, Oxlint 1.90.0, Vitest 5.0.5 + jsdom 30.1.3 + Testing Library, puppeteer-core 25.16.0 + axe-core 4.14.0.

**Spec:** `docs/superpowers/specs/2026-10-30-fm04-react-design.md` — à lire avant toute tâche : le plan en découle, la spec dit pourquoi.

## Global Constraints

- Tout se passe dans `react/` sauf indication contraire ; **`src/` (FM03, EC01) ne change jamais**.
- Versions exactes (pas de `^`) : vite 8.3.5 · react et react-dom 19.3.1 · react-router 8.5.1 · typescript 7.0.2 · tailwindcss et @tailwindcss/vite 4.3.3 · @vitejs/plugin-react 6.1.2 · oxlint 1.90.0 · vitest 5.0.5 · jsdom 30.1.3 · @testing-library/react 16.3.3 · @testing-library/dom 10.4.2 · @testing-library/user-event 14.6.8 · @testing-library/jest-dom 7.0.1 · axe-core 4.14.0 · puppeteer-core 25.16.0 · @types/react et @types/react-dom 19.3.0 · @types/node 24.19.2. `package-lock.json` commité ; jamais `--legacy-peer-deps`.
- **Jamais `react-router-dom`** : tout s'importe de `react-router` (la v8 a supprimé `react-router-dom` ; sa v7 installée à côté casse le rendu).
- TypeScript strict (options de FM03). **Zéro `any`, zéro assertion `as` (même `as const`), zéro `!` non nul, zéro `@ts-ignore`/`@ts-expect-error`** : le code de FM03 tenait cette règle, celui-ci aussi.
- Imports : extension explicite `.ts`/`.tsx` dans le code nouveau (comme le gabarit Vite) ; les fichiers repris de FM03 gardent leurs imports en `.js` (seul le chemin change).
- Noms de dossiers en anglais (fiche EC02) ; tout le reste en français (identifiants, commentaires, messages), comme FM03. Commentaires : le **pourquoi**, courts, avec la diapositive du cours quand elle existe.
- Aucun attribut `style`, aucune valeur de couleur ou de taille en dur dans les composants : les classes Tailwind des jetons (`bg-accent`, `text-m`, `rounded-m`…). Le CSS maison se limite à `src/index.css`.
- Accessibilité : un `h1` par vue (`TitreDeVue`), pas de saut de niveau de titre ; `role="list"` sur toute `<ul>` stylée ; cibles d'au moins 44 px (`min-h-11`) ; champs bordés `border-texte-doux` ; liens dans le texte soulignés ; tout bouton qui part en envoi passe en `aria-disabled="true"` (pas `disabled`) et ignore le clic pendant l'envoi.
- Les fichiers de `public/` s'écrivent `${import.meta.env.BASE_URL}images/…` (Vite ne réécrit pas les chaînes du JSX).
- `core.autocrlf=true` sur le poste : tout test qui compare des fichiers normalise `\r\n` en `\n`.
- Sous Git Bash, préfixer par `MSYS_NO_PATHCONV=1` toute commande qui passe une valeur commençant par `/`. Arrêter un serveur Node lancé en arrière-plan avec PowerShell (`Stop-Process`), `kill $!` ne le tue pas.
- Commits : en français, réalistes, une pointe d'humour mais clairs sur ce qui change ; chaque message finit par la ligne `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`. Un commit par tâche, avec le message donné.
- Commandes : lancées depuis `react/` sauf mention contraire. `npx vitest run --project <nom>` pour un projet de tests ; `npm run build` vérifie aussi les types (`tsc -b`).

  CHEMINS.formateurs,

/// <reference types="vitest/config" />
import { copyFileSync } from "node:fs";
import { resolve } from "node:path";
import tailwindcss from "@tailwindcss/vite";
import react from "@vitejs/plugin-react";
import { defineConfig, type Plugin } from "vite";
import { CHEMINS_FIXES } from "./src/router/chemins.ts";

/** L'adresse de l'application sur GitHub Pages. Absolue : une base relative (« ./ ») casse les adresses
    à deux segments (/ateliers/x chercherait ses fichiers dans /ateliers/assets/). Écrite ici et jamais
    en ligne de commande : Git Bash convertirait « /CDWS… » en chemin Windows. */
const BASE = "/CDWS-2027-FilRouge/react/";

/** GitHub Pages sert « x.html » pour « /x » : une copie de index.html par route fixe, et le rechargement
    direct de /react/ateliers répond 200 au lieu de passer par le 404.html. */
function copiesDesRoutesFixes(): Plugin {
  let sortie = "";
  return {
    name: "skillhub:copies-des-routes-fixes",
    apply: "build",
    configResolved(config) {
      sortie = resolve(config.root, config.build.outDir);
    },
    closeBundle() {
      for (const chemin of CHEMINS_FIXES) {
        copyFileSync(resolve(sortie, "index.html"), resolve(sortie, `${chemin.slice(1)}.html`));
      }
    },
  };
}

export default defineConfig({
  base: BASE,
  plugins: [react(), tailwindcss(), copiesDesRoutesFixes()],
  test: {
    // Un faux fetch (vi.stubGlobal) ne doit pas fuir d'un test à l'autre
    unstubGlobals: true,
    projects: [
      {
        extends: true,
        test: { name: "unitaires", environment: "node", include: ["tests/unitaires/**/*.test.ts"] },
      },
      {
        extends: true,

export function messageErreur(erreur: ErreurChargement): string {
  switch (erreur.raison) {
    case "reseau":
      return "La connexion semble coupée. Vérifiez votre réseau, puis réessayez.";
    case "delai":
      return "Le serveur met trop de temps à répondre. Réessayez dans un instant.";
    case "format":
      return "Les données reçues sont illisibles. Réessayez dans un instant ; si cela continue, revenez plus tard.";
    case "http":
      if (erreur.statut === 404) return "Le catalogue est introuvable pour le moment. Réessayez dans un instant.";
      if (erreur.statut !== undefined && erreur.statut >= 500) return "Le serveur rencontre un problème. Réessayez dans un instant.";
      return "Le serveur a refusé la demande. Réessayez dans un instant.";
  }
}

/** Le prénom, pour saluer : le premier mot du nom saisi (déjà débarrassé de ses espaces autour). */
export function prenomDe(nom: string): string {
  return nom.split(/\s+/)[0] ?? nom;
}
